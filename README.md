# Snake

> 个人练习项目。目标不是做一款完整的游戏，而是把 **固定步进 / 输入缓冲 / 数据与表现分离** 这三件事写扎实。
> 引擎版本：Unity 2022.3.62f3c1 · 模板：3D（Built-in）· 全部使用自带几何体占位，不引入外部美术

---

## 一句话玩法

方向键控制蛇在 20×20 的网格上移动，吃到食物长度 +1、分数 +1，撞墙或撞到自己就结束。

## 操作

| 按键 | 作用 |
|---|---|
| ↑ ↓ ← → | 转向（不能 180° 掉头） |
| R | 死亡后重开 |

最高分保存在本地（`PlayerPrefs`），关掉游戏不会丢。

## 运行

1. Unity 2022.3.62f3c1 打开项目
2. 打开 `Assets/Scenes/SampleScene.unity`
3. 按 Play

## 脚本结构

```
Assets/_Project/Scripts/
  Snake.cs       数据与规则：身体坐标、方向、食物、分数、最高分
  SnakeView.cs   表现：把格子坐标画成方块，不认识任何规则
  GameHUD.cs     界面：得分、最高分、结算面板
```

三个脚本共约 300 行。没有用预制体，棋盘、蛇、食物都是运行时用 `CreatePrimitive` 生成的。

## 几个值得说明的设计

### 1. 移动是固定步进，不是每帧走

蛇每 0.3 秒走一格，由协程控制：

```csharp
while (!isDead)
{
    yield return new WaitForSeconds(interval);
    // 取一个输入 → 走一格 → 同步画面
}
```

`Update` 只负责读键盘，不负责移动。如果让移动跟着帧率走，同一局在 60 帧和 144 帧的机器上速度会不一样。

顺带一提：`WaitForSeconds` 受 `Time.timeScale` 影响，所以将来做暂停时，协程会自动跟着冻住。

### 2. 输入必须排队，只存一个是错的

最初的写法是 `Update` 里直接改 `dir`。问题在于：一次移动间隔是 0.3 秒，这期间 `Update` 会跑十几帧，玩家可能按好几次方向。

向右走时快速按 ↑ 再按 ←，会直接撞死自己。原因是“不能 180° 掉头”的守卫拿 `dir` 做比较，而 `dir` 已经被上一步按键改成了 `Up`——`Left` 相对于 `Up` 是合法的 90° 转弯，守卫放行了，但蛇的身体还在右边。

改成两个变量后问题消失：

- `dir`：这一格**正在走**的方向，只有 tick 能写
- `pending`：**还没轮到**的方向，只有 `TryTurn` 能写，最多存 2 个

校验的基准也换成了**队尾**而不是 `dir`——判断“能不能转”要看“上一个还没执行的意图”，因为玩家按 ↑ 再按 ← 的意思是走一个 L 形弯。

### 3. 身体由方向生成，用约束代替“记得对齐”

蛇身上有一条不变式：

```
body[1] == body[0] - dir
```

正常的蛇每走一格，新头从 `body[0] + dir` 长出来，旧头退成 `body[1]`，所以第二节永远待在头的正后方。

开局时手写身体坐标很容易破坏它。最初的写法是 `body.Add(new Vector2Int(-i, 0))`，身体横向排在左边，而 `dir` 声明为 `Up`——两个状态互相矛盾。结果开局按一下 ← 就是直接走进自己的身体。

改成从 `dir` 推出身体，约束由构造保证，不可能写错：

```csharp
for (int i = 0; i < startLength; i++)
    body.Add(-dir * i);
```

### 4. 尾巴在移动的同一瞬间让位

判定“目标格能不能进”时，直觉是检查整条身体。但这样会误杀一种情况：蛇绕回来，头要进的那一格正好是尾巴现在的位置。

尾巴在移动完成的瞬间就会移开，所以那一格是空的。真正该问的不是“这一格现在有没有人”，而是“**移动完成之后**这一格还有没有人”。

区别只在于这次是不是吃到了食物：

```csharp
int limit = eats ? body.Count : body.Count - 1;
```

吃到食物时身体加长、尾巴留在原地，那一格仍然是实心的；没吃到时尾巴前移，让出原来的位置。

这个 bug 平时玩不出来，要把蛇养长、绕一个圈才会触发。

### 5. 规则不认识表现

`Snake` 只做两件事跟画面有关：

```csharp
view.Build(boardSize, cellSize);
view.Render(body, food, isDead);
```

`SnakeView` 里没有任何一行写着 `Snake`。它不知道谁在调它，也不知道为什么会死，只收到三个参数然后画出来。

依赖是单向的，所以改动不会往外扩散：换贴图、给蛇头加朝向、食物转起来，只改 `SnakeView`；加障碍物、调速度、改棋盘大小，只改 `Snake`。

棋盘尺寸只由 `Snake` 持有，通过 `Build()` 传进 View。如果两个脚本各配一份，改了一个忘了另一个，蛇会在地板边缘外面两格就撞死，而且很难看出原因。

## 已知限制

- 食物生成每次遍历全盘，棋盘小可以接受，棋盘大就要换算法
- 每次 `Render` 都从头同步所有方块，蛇很长时是 O(n)，可以只更新变化的头尾
- 没有音效，没有移动端输入
- 只有一个场景，没有主菜单
